# Сессии, отключения и доступ — шаг 4.13

## Тайм-аут и удаление

- [NetworkConfig](../src/net/network_config.gd) / [default_network.tres](../src/net/default_network.tres): `client_timeout_seconds = 10.0`, `activity_poll_seconds = 0.1`, `timeout_factor = 32`, начальный `blocked_ips`. Протокол 9 включает серверную команду в payload спавна.
- [PeerLifecycle](../src/net/peer_lifecycle.gd) принадлежит Net. После hello/welcome запоминает монотонное время последнего пакета каждого допущенного соединения. Ввод, fire, чат, подтверждения карты/сущности, параметры симулятора и ping/pong обновляют серверный срок; снапшоты, боевые события, патроны, косметика, чат и карта — клиентский. Чужой/неизвестный peer не создаёт запись активности. Локальный listen-host не получает сетевой тайм-аут.
- При `now - last_received >= 10 секунд` один постоянный Timer публикует `peer_timed_out`. Проверка выполняется раз в 0.1 с, независимо от паузы и масштаба игрового времени. Повторного события для удалённой записи нет. Нормально подключённый неподвижный клиент продолжает присылать ввод и пробы часов; ENet ACK сами по себе не скрывают зависший игровой процесс.
- Дополнительно на прямых ENetPacketPeer обеих сторон задаются документированные `set_timeout(32, 10000, 10000)` и `ping_interval(500)`. Клиентские уведомления о других игроках — ретранслированные id, для них прямого ENet peer нет. Одного ENet timeout недостаточно: в проверке его экспоненциальные повторы давали около 15 с; прикладной контроль обеспечивает требуемый срок.
- Сервер выводит `NET TIMEOUT id=...`, удаляет получателя через `SceneMultiplayer.disconnect_peer()` и очищает присутствие. Этот API сначала удаляет получателя из репликации и кешей, затем закрывает ENet. Прямое закрытие транспорта раньше очистки воспроизводило ошибку канала 0; исправление проверено сценарием с пропавшим клиентом. Прежнее отдельное наблюдение массового внешнего закрытия сокетов в BLOCKERS не переоценивалось.
- `peer_left` публикуется один раз. [NetworkPlayers](../src/net/network_players.gd) сохраняет последнюю серверную команду, удаляет ready, немедленно выключает обработку игрока и ставит его на удаление в конце кадра. `tree_exiting` очищает слот спавна, lag tracks, снапшоты/очереди, подписки боя и респавна. Таймеры рукопожатия/закрытия и часы соединения также очищаются.
- При кике допуск отзывается сразу; имеющиеся 0.2 с оставлены для доставки причины. Клиент при отсутствии серверных пакетов получает `server_timeout`, выгружает мир и возвращается в меню. Начальное рукопожатие сохраняет отдельный срок 5 с.

## Ник и команда

- Существующий HandshakeRules отклоняет занятый ник без учёта регистра (`nickname_in_use`) и неверный пароль (`wrong_password`). Проверки и ограничения ника сохранены.
- [NetworkSession](../src/net/network_session.gd) хранит соответствие принятого peer нику и последнюю положительную команду по `nickname.to_lower()`. Команда записывается перед удалением серверного Player, пока запись соединения ещё доступна; затем peer забывается. Другой ник не наследует команду.
- Повторный вход с тем же ником получает команду в серверном payload MultiplayerSpawner. `Player.team_id` назначается до `_ready`, поэтому CombatAffiliation и клиентская реплика сразу согласованы. Новая система выбора/баланса команд не добавлена.
- Команды и списки существуют в памяти одного запущенного сервера; Disconnect/новый Host очищают историю. Ник является идентичностью только этой сессии, постоянных аккаунтов нет.

## Пароль, кик и чёрный список

Серверный пароль задаётся прежним полем Password в меню Host или `--password=...` при выделенном запуске. Join использует то же секретное поле. Пароль администратора независим: `--admin-password=...`; после входа в чат — `/admin <password>`. Пароли не реплицируются другим игрокам и не пишутся в логи.

Администратор текущего соединения может выполнить:

| Команда | Результат |
| --- | --- |
| `/kick <peer_id\|nickname>` | Отключает игрока; последующий вход разрешён |
| `/ban <peer_id\|nickname\|IP>` | Добавляет IP в сессионный список и отключает все текущие соединения с этого IP |
| `/unban <IP>` | Удаляет IP из списка текущей сессии |
| `/blacklist` | Показывает отсортированный список только запросившему администратору |

IP игрока берётся сервером из ENetPacketPeer.get_remote_address, клиент его не назначает. При буквальном IP допускаются IPv4/IPv6; эквивалентные сокращённые/полные IPv6 и IPv4-mapped формы нормализуются, имена хостов отклоняются. Бан по IP распространяется и на другие ники и соединения за тем же адресом/NAT.

Для начального списка изменить `blocked_ips` в ресурсе настроек, например `PackedStringArray("192.0.2.10")`. Проверка выполняется сразу после транспорта, до допуска hello и спавна (`ip_banned`). Изменения командами действуют до конца сессии; новый сервер заново применяет ресурс. Сам сервер listen-host защищён от кика/бана по peer_id.

Проверены лимиты 300/40, `git diff --check` и сохранность SHA-256 трёх пользовательских файлов.
