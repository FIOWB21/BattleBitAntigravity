# Поток ввода и серверная симуляция (шаг 4.4)

[InputCodec](../src/net/input_codec.gd) описывает один кадр из 12 байт little-endian:

| Смещение | Поле | Формат |
| --- | --- | --- |
| 0–1 | move.x / move.y | 2×int8, масштаб 127 |
| 2–3 | yaw | uint16, 0..TAU |
| 4–5 | pitch | uint16, −PI/2..PI/2 |
| 6–7 | buttons | uint16 |
| 8–11 | tick | uint32 |

После декодирования проверяются конечность значений, длина направления ≤1.01,
известные биты кнопок и pitch ±89° с допуском квантования. Нулевой тик не является вводом.
Формат передаёт только эти пять полей. Отдельные команды слотов, колеса, последнего
оружия, гранаты и ножа остаются офлайн.

[InputHistory](../src/net/input_history.gd) хранит кольцо последних 6 кадров (72 байта).
Незаполненные записи имеют tick=0 и игнорируются. LocalInputReader.read_into использует
прежний сбор без создания нового PlayerInput на каждом физическом тике.

[ServerInputQueue](../src/net/server_input_queue.gd) прогревает 128 записей и принимает
тики в окне ±1 с относительно сервера. Дубликаты, уже обработанные и невалидные вводы
отбрасываются. Сервер читает самый ранний ввод ровно один раз за серверный тик.
При пустой очереди последний ввод повторяется максимум 5 тиков; затем move/buttons=0,
углы сохраняются. Просроченные записи удаляются также перед потреблением.

Исходный last_input_tick хранится отдельно. Игровой inp.tick всегда серверный, поэтому
повтор ввода не останавливает сроки оружия. Параметры находятся в NetworkConfig и
default_network.tres; объекты и массивы прогреваются вне физического цикла.

Владелец после синхронизации NetClock шлёт историю каждый физический тик через
ServerPlayerSim.submit_input: any_peer/call_remote/unreliable_ordered, канал 1.
Сервер сверяет sender с владельцем сущности и принятым Net.nicknames. Сущность создаётся
только после map_ready. Listen-host проходит тот же кодек и очередь локальным вызовом.
Сигнал input_simulated сообщает обработанный ввод; клиент игровую симуляцию не выполняет.
Клиентские позиции пока сохраняют спавн: передачи состояния в этом шаге нет.

[Модульные тесты](../tests/unit/net/) проверяют round-trip, потери, порядок, дубликаты,
границы, повторы и совпадение мотора. [Межпроцессный тест](../tests/integration/test_input_delivery.gd)
использует реальный ENet и проверяет подмену владельца, диагонали и будущего тика,
пять повторов перед остановкой и совпадение серверного прогона с локальным.
