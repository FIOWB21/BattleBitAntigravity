# Чат и команды администратора — шаг 4.11

## Использование

- Открыть сетевое меню `src/ui/main_menu.tscn`, создать сервер или присоединиться.
- Enter открывает поле. Выбрать All или Team, отправить Enter; Esc закрывает поле. Во время набора движение, огонь и буферизованные игровые действия блокируются, затем управление восстанавливается. Действие `chat` также открывает поле при отдельной привязке: текущая InputMap назначает T одновременно chat и switch_weapon_last, поэтому T оставлена смене на прошлое оружие; Enter служит входом в чат. Пользовательская InputMap не изменяется.
- История содержит восемь переиспользуемых Label с переносом текста в ограниченном ScrollContainer. Автопрокрутка следует изменению размеров; длинные строки не вытесняют поле ввода. Старые сообщения вытесняются; переподключение очищает историю. Парсер BBCode отсутствует.
- Сервер запускается с `-- --server --admin-password=<password>`; listen-host получает тот же параметр при запуске без `--server`. Пароль администратора отделён от пароля входа на сервер. Пустое значение отключает административный доступ.
- Авторизация: `/admin <password>`; ответ видит только отправитель. Поле маскирует ввод пароля, очищается после отправки и не хранит историю команд. Команды и пароль не попадают в чат или логи приложения.
- `/kick <peer_id|nickname>` отключает принятого клиента; идентификатор 1 защищён. Допуск отзывается сразу, узел сохраняется до завершения транспорта, чтобы запоздавший ввод не обращался к удалённому пути.
- `/map <map_id>` использует только каталог MapLoader. Сейчас зарегистрирована `testbed`; эта команда перезагружает её. Неизвестный id отклоняется. Смена геометрии сохраняет сетевые Player и пути RPC, сервер восстанавливает здоровье, комплект, позиции и истории через RespawnService/SpawnState. Надёжное map_changed предшествует player_spawned в канале 0. Авторизация и история чата сохраняются в пределах соединения.
- `/say <text>` публикует объявление SERVER всем готовым участникам, включая противников.

## Серверный контракт

[NetworkChat](../src/net/network_chat.gd) находится под постоянным MapLoader; новых автолоадов нет. `submit(text, team_only)` — any_peer/reliable канал 0. Источник берётся из remote_sender_id, проверяется по Net.nicknames, ready_peers и серверному actors. Клиент не передаёт имя, peer_id или team_id. Локальный listen-host проходит те же проверки без RPC самому себе.

Командное сообщение доставляется отдельным `deliver` только готовым принятым игрокам с тем же положительным серверным Player.team_id. Противник не получает payload, даже если поменял локальные team_id. Dedicated не является получателем сообщений игрока. Обычный чат и SERVER объявление доставляются всем готовым участникам. Текущие серверные Player по умолчанию имеют team_id=1; шаг использует существующее поле и не добавляет распределение команд.

[ChatConfig](../src/net/chat_config.gd) / [default_chat.tres](../src/net/default_chat.tres): максимум 256 Unicode-символов результата, максимум 1024 символа входного запроса, три запроса за скользящее окно 5 с на peer. Лимит общий для текста, пустых/некорректных запросов, команд и попыток авторизации; часы только монотонные серверные. Отклонённые по частоте запросы не добавляются в окно и не вызывают ответного потока. Каждый peer хранит не более трёх временных меток. Отключение очищает окно и права, смена карты их сохраняет.

[ChatPolicy](../src/net/chat_policy.gd) удаляет представимые C0/C1, невидимые управляющие/направляющие Unicode-символы и разделители строк; квадратные скобки превращает в круглые. Затем убирает краевые пробелы и обрезает по Unicode-символам. Emoji и кириллица сохраняются. NUL не представим в Godot String: движок отклоняет его до вызова санитайзера. Санитайзер не является фильтром ненормативной лексики.

Все RPC доставки/уведомления/смены карты имеют authority/reliable. `/admin` проверяется на сервере, права живут только до отключения; ошибочный повторный вход снимает их. Конфигурация пароля не реплицируется. Протокол повышен до 7. ENet обеспечивает транспорт, но не шифрует пароль администратора; использовать доверенную сеть/VPN для удалённого администрирования.

## Проверки и ограничения

- [Модульные тесты](../tests/unit/chat/) покрывают санитайзер, идемпотентность, Unicode, точные границы окна, независимость/очистку peer, конфигурацию, пароль/права, серверный выбор получателей, запрет неподтверждённых отправителей, нейтральный ввод и Label без создания узлов на сообщение.
- Проверки карты сохраняют instance_id и текущую геометрию при отказе; перезапуск восстанавливает жизнь, патроны, позу, очередь ввода и очищает сроки респавна. [Тест аргументов](../tests/unit/test_server_arguments.gd) проверяет пробелы/`=` в пароле, сброс и отсутствие секретов в ошибках.
- [ENet-приёмка](../tests/integration/chat/test_chat_delivery.gd) / [worker](../tools/chat_worker.gd): dedicated + три клиента и listen-host + два клиента. Общий/командный чат через настоящий UI и RPC, подмена локальной команды врагом, обрезка 300→256, антиспам, отказ без прав/с неверным паролем, `/say`, неизвестная карта, `/map testbed`, `/kick Enemy` и чат после смены. Логи проверяются на ошибки, предупреждения и отсутствие пароля.
- Автоматические логи находятся в `.godot/chat_*`; полный запуск — `tools/check.sh`. Итоговые числа и визуальная самопроверка фиксируются в PROGRESS.md.
- 🧑 Внешняя сеть, длительный чат и удобство интерфейса человеком не проверены. Для ручного повтора использовать двух союзников и противника с разными серверными team_id; убедиться, что Team не появляется у противника, проверить команды и возврат управления после Enter/Esc.
